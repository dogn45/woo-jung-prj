# NIGHT / 24 — 심야 편의점 베이스 프로토타입

사용자 명세를 바탕으로 제작한 **Godot 4.4.1 기준 실행 가능한 소스 프로젝트**입니다
완성된 상용 공포게임이 아니라, 기본 근무 루프를 검증하고 확장하기 위한 회색 박스 버전입니다

## 바로 실행

1. ZIP 전체를 압축 해제하세요
2. Godot **4.4.1 Standard** 또는 이후 4.x 버전에서 프로젝트 가져오기(Import)를 누르세요
3. 이 폴더의 `project.godot`를 선택하세요
4. 최초 리소스 가져오기가 끝나면 **F5**로 실행하세요
5. 시작 화면에서 **00:00 근무 시작**을 누르세요

별도 모델 다운로드, 유료 에셋, 플러그인, .NET은 필요하지 않습니다
Godot 3.x는 지원하지 않습니다 / 다른 4.x 버전에서는 추가 확인이 필요합니다
Windows 실행 파일(.exe)은 포함하지 않았으며 Godot 편집기에서 실행하는 프로젝트입니다
소스 편집기에서의 F5는 게임 실행, 게임 창에 포커스가 있을 때의 F5는 저장입니다

아무 곳에 던지기, 자유 물리, 양손 대형 물체 운반은 구현하지 않았습니다

## 설계 분석과 다음 순서

가장 큰 개발 부담은 편의점 모델 수가 아니라, 양손 상태·물건 상태·업무·NPC·저장을 서로 맞추는 작업입니다
현재 프로젝트는 모든 잡을 수 있는 물건에 고정 ID를 부여하고, 손과 진열 칸의 점유 상태를 따로 기록합니다
저장에서는 시간, 위치·시점, 양손 물건, 물건 위치·활성·스캔 상태, 진열 상태, 문, 전원, 업무, NPC 상태·이동 단계, CCTV 채널을 복원합니다
저장 중 손이 움직이는 상황을 피하도록 자동 저장은 동작 완료까지 미룹니다

TimeManager는 시각과 시간 신호만 담당합니다
NPC·조명·업무는 그 시각을 사용하며, 미래 공포 이벤트는 별도 EventDirector를 두는 편이 수정하기 쉽습니다
선택 중인 CCTV 화면 하나만 렌더링해 다섯 화면을 동시에 그리는 비용을 피했습니다

다음 개발은 아래 순서가 적절합니다

1. 이 회색 박스에서 10~15분의 업무 루프를 실제로 플레이하고 동선 확정
2. Godot 에디터에서 편집할 개별 .tscn으로 매장·소품 분리
3. 플레이어 몸과 팔을 리깅 모델로 교체하고 손가락·문손잡이 동작 개선
4. NPC를 NavigationAgent3D와 줄서기 시스템으로 확장
5. 업무 조건·기한과 물건 종류를 Resource 데이터로 분리
6. 규칙 1개 + 공포 사건 1개 + 엔딩 1개로 짧은 수직 슬라이스 완성
7. 그 뒤에 2.5~3.5시간 분량으로 확장할 가치가 있는지 검증

지금 기획만으로 3시간이 재미있다고 판단할 근거는 없습니다
시간 설정은 구현했지만, 콘텐츠 밀도·반복 피로·실패 후 재시작 비용은 실제 플레이로 결정해야 합니다

## 파일 구조

- `main.tscn` — 시작 장면
- `scripts/game.gd` — 실행 조립·입력·업무 상호작용·HUD·메뉴
- `scripts/world_builder.gd` — 매장과 외부 공간 생성 / 좌표·배치 수정
- `scripts/player.gd` — CharacterBody3D 이동·RayCast3D·양손·임시 몸
- `scripts/interactable.gd` — 공통 상호작용 오브젝트
- `scripts/time_manager.gd` — 시각·근무 시간 / `real_shift_minutes = 180.0`
- `scripts/task_manager.gd` — 기본 4개 업무
- `scripts/customer.gd` — 손님 상태와 고정 이동 경로
- `scripts/cctv.gd` — SubViewport·5개 시점·모니터
- `scripts/save_manager.gd` — JSON 저장·검증·복원
- `scripts/geometry.gd` — 임시 도형·재질·텍스트·조명 생성
- `assets/` — 포함된 합성 사운드와 한글 폰트
- `tests/smoke.gd` — 핵심 동작 자동 검증
- `tests/capture.gd` — 실제 렌더링 이미지 생성용 스크립트
- `tests/*.png` — 실제 엔진 화면 캡처
- `VALIDATION.txt` — 검증 결과와 한계

맵은 실행 시 코드로 생성됩니다 / 편집기에서 main.tscn만 열었을 때 빈 장면처럼 보이는 것은 정상입니다
실행 후 Godot의 Remote 장면 트리에서 생성된 노드를 확인할 수 있습니다
지금은 배치 변경을 `world_builder.gd`에서 하며, 본격 모델링 단계에 각 공간을 .tscn으로 분리하는 것이 좋습니다

## 저장 파일

Godot의 `user://nightshift_v1.json`을 사용합니다
Windows 저장 폴더: `%APPDATA%/NightShiftPrototype/`
정확한 위치는 Godot에서 `OS.get_user_data_dir()`로 확인하세요
이전 저장은 `.bak`, 작성 중 파일은 `.tmp` 확장자를 사용합니다
.bak 복원 UI는 없으며 필요 시 백업 파일을 원래 JSON 이름으로 수동 복사하세요
새 근무를 시작해도 기존 저장은 다음 저장 때까지 유지됩니다
F9 불러오기는 현재 진행을 저장한 시점으로 되돌립니다

## 재검증

프로젝트를 한번 에디터에서 가져온 후 명령줄에서 실행할 수 있습니다

```sh
godot --headless --path . --script res://tests/smoke.gd
```

테스트는 `user://smoke_save.json`, `user://smoke_corrupt.json`을 사용합니다
실제 화면 캡처는 그래픽 디스플레이가 있는 환경에서 실행하세요

```sh
godot --path . --script res://tests/capture.gd
```
